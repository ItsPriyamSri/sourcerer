Why the brain has to be on the device

The decision happens in a basement with no bars, so the model has to be in your hand. That isn't ideology — it's plumbing.

The model reads

fuzzy · tolerant of bad light · right most of the time

Identification is exactly the job a small open-weight vision model is good at. It doesn't need to be perfect; it needs to be fast, private and free at the margin.

Arithmetic decides

deterministic · unit-tested · identical offline

The money is never left to a language model. Fees, shipping and the max offer are plain functions, so the number you get in a basement equals the number you get online.

Honest limits

  • It is slow on CPU. Roughly nine seconds per item once the model is warm, and about forty seconds on the very first photo of a session while the weights load. A GPU changes this; this laptop's doesn't.
  • eBay's real sold prices are not available. eBay moved completed listings behind a login and the search API's sold filter went with them. The app returns live asking prices, labels them as asking, and applies a visible 14% haircut. It is a range, not a promise.
  • Gemma 3 4B cannot call tools. Identification and writing work; the tool-using advisor needs a different open model beside it. The app says so instead of failing quietly.
  • The price model needs your data. With no sold history it falls back to condition-adjusted comps and a deliberately pessimistic guess. It gets personal only after you log sales.

Built with

Open weights at the core, open source around it. Every one of these sits behind a fallback, so removing any of them degrades the app instead of breaking it.
